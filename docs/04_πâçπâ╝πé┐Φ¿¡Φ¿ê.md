# 04 データ設計

データの形は2か所で定義しています。

- **アプリ内のデータの形**：`core/src/types.ts`（TypeScript の型）
- **データベース**：`db/schema.sql`（PostgreSQL + PostGIS。Supabase にそのまま流せます）

## 中心になる考え方

### 1. 「走った道」は区間 ID で持つ
走行の軌跡（GPSの点の列）をそのまま重ねて描くと、走行回数に比例して重くなり、「どこを走ったか」の判定もできません。
そこで、道路を交差点で区切った**区間（road_edges）**を用意し、走行ごとに「どの区間を走ったか」（ride_edges）を保存します。

- 白地図の描画 → 走った区間を描くだけ（何百回走っても区間数以上には増えない）
- 開拓率 → 走った区間の長さ ÷ 地域全体の長さ
- 未走行ルート提案 → 走っていない区間を探す
- 招待状・地図の重ね合わせ → 区間 ID のやりとりで済む

### 2. 生の軌跡と、他人に見せる線を分ける
| データ | 誰が見られるか | 置き場所 |
|---|---|---|
| 生の軌跡（全GPS点・時刻・速度） | 本人だけ | ストレージ `rides/{user_id}/{ride_id}.json` |
| 間引いた軌跡 `rides.track` | 本人だけ | DB |
| 隠す範囲を除いた軌跡 `rides.shared_track` | 公開範囲に応じて | DB |
| 隠す範囲 `privacy_zones` | 本人だけ | DB |

他人向けの線は、**サーバー側で**隠す範囲を取り除いてから保存します（`mask_line_for_user` 関数、または `core` の `maskLine`）。端末側でも同じ処理をしてプレビューに使います。

### 3. 道路データは地域単位で入れ替えられるように
`road_edges.region` で地域を分けています。最初は1〜2地域でテスト公開し、地域を追加していく想定です。

## 誰が何を見られるか（行レベルセキュリティ）

`db/schema.sql` の末尾で定義しています。PostgreSQL 16 + PostGIS で次の動作を確認済みです。

- 招待状を受け取った人は、その招待状を読める
- 招待状と関係ない人は読めない
- 他人の「隠す範囲」は誰も読めない
- `mask_line_for_user` で隠す範囲を取り除ける

| データ | 本人 | 友達 | 招待状の受取人 | その他 |
|---|---|---|---|---|
| 走行記録・軌跡 | 読み書き | ×（段階2で shared_track のみ） | × | × |
| 隠す範囲 | 読み書き | × | × | × |
| 写真 | 読み書き | ×（段階2で共有を選んだもの） | 招待状の表紙のみ | × |
| 招待状 | 作成・削除 | × | 読む・保存・通知の許可 | × |
| プロフィール | 読み書き | 読む | 読む | 読む（ログイン中） |
| 道路データ | 読む | 読む | 読む | 読む |

## 端末内のデータ

通信できない場所での記録に備えて、記録中の GPS 点は端末内に保存し、保存操作のあとでまとめて送ります。

- Web：IndexedDB
- スマホアプリ：SQLite など

送信に失敗した記録は端末に残し、次回起動時に再送します。

## 道路データの作り方（概要）

1. OpenStreetMap などから対象地域の道路を取り出す
2. 交差点で区切って区間にする（ノード＝交差点、区間＝交差点間の道）
3. 種別（`highway` タグ）を `RoadType` に対応させる
4. 海沿い・峠・湖畔などの特徴を付ける（海岸線・湖からの距離、標高差などで判定）
5. 二輪規制の情報を付ける（`motorcycle=no` などのタグ。網羅性は要確認、`docs/08`）
6. `road_edges` に読み込む

この作業は「道路データ準備」として `docs/06` の段階1に入れています。
