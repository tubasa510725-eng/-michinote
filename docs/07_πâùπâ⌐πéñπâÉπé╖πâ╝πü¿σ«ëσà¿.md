# 07 プライバシーと安全

ミチノートは**毎回の移動経路**という、とても扱いに注意が必要なデータを預かります。信頼を失うと取り返しがつかないので、最初から設計に組み込んでいます。

> このページは設計上の方針です。法律上の判断ではありません。公開前に、プライバシーポリシーや利用規約を専門家に確認してもらってください。

## 位置情報

### 原則
1. **既定は「自分だけ」。** 走行記録は、本人が選ばない限り誰にも見えない。
2. **自宅周辺は自動で隠す。** 共有するデータからは、隠す範囲（既定半径1km）の中の線・スポット・写真を取り除く。さらに走行の始点・終点から200mも削る。
3. **隠す範囲そのものは誰にも渡さない。** 「どこが隠されているか」から自宅が推測されないよう、隠す範囲の中心・半径はAPIの応答に含めない。
4. **生の軌跡は本人だけ。** 他人に見せるのは、間引き・隠す処理をした線だけ。走行時刻・速度も渡さない。
5. **共有前に必ずプレビュー。** 相手に何が見えるかを本人が確認してから送る。

### 実装上の対応
| 原則 | 実装 |
|---|---|
| 自宅周辺を隠す | `core` の `maskLine` / `maskEdges` / `maskPoints`、DB の `mask_line_for_user` |
| 招待状に余計な情報を入れない | `buildInvite` の戻り値は渡してよいデータだけ（テストで確認済み） |
| 他人のデータを読ませない | `db/schema.sql` の行レベルセキュリティ |
| 写真の位置情報 | アップロード前にEXIFの位置を削除する |

### 気をつけたいこと
- **繰り返しのパターン。** 隠す範囲の外でも、毎回同じ場所で途切れる線が多いと推測の手がかりになり得る。地図の重ね合わせ（段階2）では、隠す範囲の境界付近をぼかす、範囲を走行ごとに少しずらすなどを検討する。
- **リアルタイムの位置共有はしない。** スライド4の注意書きのとおり、「常時の現在地共有」とは別の機能として、過去の記録を選んで共有する。
- **退会時の削除。** 退会したら軌跡・写真・招待状を削除する（`on delete cascade` で設計済み。ストレージのファイルも消す処理が必要）。

### 法令・ストアまわりで確認すること
- 位置情報はアカウントと結びつくと個人情報として扱われる。利用目的・第三者提供・保存期間をプライバシーポリシーに明記する。
- iOS / Android ともに、バックグラウンドで位置情報を使う理由の説明と、ストア審査での申告が必要。
- 写真に写り込んだ他人の顔やナンバープレートの扱い（共有アルバム・現地メモ）。

## 走行中の安全

- **記録の開始・終了は停車中に。** 走行中（目安：時速10km以上）は開始・終了ボタンを押せない、または確認を出す。
- **走行中は操作不要に。** 記録中の画面は大きな表示だけ。通知は走行中に出さず、停車後にまとめる。
- **運転中のスマホ操作は法律で禁止されている。** アプリ内でも「停車してから操作してください」と案内する。

## 提案ルートの安全

- **二輪規制・通行止めの区間は提案しない。** データにある限り、条件に関係なく除外する（`motorcycleBanned`）。
- **データが完全ではないことを伝える。** 「所要時間は目安です。通行規制・道路状況は出発前に確認してください。」を常に表示する。
- **狭い山道を避ける選択肢を用意する。** 大型車・足つきが不安な人向け。
- **冬季閉鎖・夜間通行止め** は段階1では持たないので、注意書きで補う。将来は季節・時間帯の規制情報を検討する。

## 投稿情報（現地メモ、段階3）

- **訪問日を必須にする。** 古い情報を区別して表示する。
- **体験情報であることを明記する。** 「営業・駐輪可否・道路状況は変わるため、訪問前に確認してください。」
- 店舗や私有地への迷惑につながる投稿（無断駐輪の推奨など）を通報・削除できるようにする。

## 交流機能（段階2）

- ブロック、通報、メッセージの受信範囲（友達のみ／誰でも）を最初から用意する。
- ブロックした相手からは招待状・DMが届かない（`recipients_insert` のポリシーで設計済み）。
