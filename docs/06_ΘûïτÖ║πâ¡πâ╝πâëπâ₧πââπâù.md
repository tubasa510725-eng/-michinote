# 06 開発ロードマップ

期間は**開発者1人がほぼ専任**の場合のおおまかな目安です。経験・使う技術・道路データの入手状況で大きく変わります。

## 全体像

| 段階 | 目的 | 主な中身 | 目安 |
|---|---|---|---|
| 0 準備 | 決めるべきことを決める | 技術選定、地域の選定、道路データの入手方法、アプリ名 | 1〜2週間 |
| 1 MVP | 1人で使って楽しいか確かめる | 白地図・記録と写真・未走行ルート提案・道の招待状 | 2〜4か月 |
| 2 つながり | 友達どうしで使えるようにする | QR/IDで友達、DM、地図を重ねる、二人に合う旅 | 2〜3か月 |
| 3 共有と情報 | 記録を見せたくなる・役立つ | 共有アルバム、アルバム動画、現地メモ | 2〜3か月 |

## 段階0：準備

- [ ] 技術を決める（`docs/05`）
- [ ] テスト公開する地域を1〜2か所決める（ライダーが多く、海沿い・峠・湖がそろう地域が試しやすい）
- [ ] 道路データの入手方法と、二輪規制情報の扱いを決める（`docs/08`）
- [ ] アプリ名を決め、商標・ストアでの重複を確認する
- [ ] プライバシーポリシーの方針を決める（`docs/07`）

## 段階1：MVP

### 1-1 土台（2〜3週間）
- [ ] プロジェクト作成、`core/` を組み込む
- [ ] `db/schema.sql` を流してバックエンドを用意
- [ ] ログイン、プロフィール、愛車登録
- [ ] 自宅周辺（隠す範囲）の設定

### 1-2 道路データ準備（2〜4週間、1-1と並行可）
- [ ] 対象地域の道路を区間に分割して `road_edges` に読み込む処理
- [ ] 種別・海沿い・峠・湖畔・狭い・二輪規制の付与
- [ ] 白地図のスタイル（海岸線・湖・県境）

### 1-3 白地図と記録（3〜5週間）
- [ ] マイ地図／ナビ地図の表示と切り替え
- [ ] GPS 記録（開始・終了は停車中、通信がなくても記録）
- [ ] 保存処理：`cleanTrack` → `rideStats` → `detectStops` → `matchEdges` → `firstTimeEdges`
- [ ] 写真の追加・EXIF位置の削除・ルート上への配置
- [ ] 統計（走った距離・開拓率）と「地図が育つ」再生

### 1-4 提案と招待状（3〜4週間）
- [ ] ルート提案の画面と `suggestRoutes` の組み込み、ナビアプリへの受け渡し
- [ ] 招待状の作成（`buildInvite`、プレビュー）・送信・受信・保存
- [ ] 実走の判定（`inviteProgress`）と、許可制の通知

### 1-5 仕上げとテスト公開（2〜3週間）
- [ ] 履歴と簡易アルバム、記録の削除
- [ ] 実際に走ってのテスト（距離の誤差、電池の減り、通信のない場所）
- [ ] 提案の重みの調整
- [ ] 少人数（10〜30人）でテスト公開し、`docs/01` の成功の目安を計測

## 段階2：つながり
- 友達（QR/ID）、ブロック、通報
- DM・少人数グループ（受信範囲の設定）
- 地図を重ねる（共有する期間・地域・愛車を選べる）
- 二人に合う旅を探す（出発地が違う場合の扱いを設計）

## 段階3：共有と情報
- 共有アルバム（参加者が写真を選んで持ち寄る）
- アルバム動画（白地図に道が描かれ写真が現れる、SNS向けの短い動画）
- 現地メモ（駐輪場所・路面・坂・訪問日。古い情報の区別）

## テスト方針

| 対象 | 方法 |
|---|---|
| `core/` の計算 | 自動テスト（`npm test`）。機能を変えたらテストも足す |
| 閲覧ルール | テスト用DBで「他人のデータが見えないこと」を確認するテストを用意する（`db/schema.sql` の動作確認と同じ考え方） |
| GPS 記録 | 実走テスト。録った軌跡をテスト用データとして保存し、`core` のテストに追加していく |
| 画面 | 主要な流れ（記録→保存→地図に反映、提案→記録、招待状の送受信）を自動テスト |
