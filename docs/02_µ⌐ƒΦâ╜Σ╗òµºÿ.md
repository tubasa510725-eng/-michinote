# 02 機能仕様

最初のリリース（MVP）で作る機能の詳細です。各機能に「受け入れ条件」を付けています。開発の完了判定やテストの観点に使ってください。

関数名は `core/` の実装を指します。

---

## 0. 共通

### アカウント
- メールアドレス、Apple、Google でのログイン（Apple でのログインは iOS アプリで他社ログインを提供する場合に求められることがあるので、ストア公開時に要確認）。
- 初回にハンドル名（例：`sora_rider`）、表示名、愛車を1台登録。愛車は後で追加できる。

### 初回設定：自宅周辺を隠す範囲
- 初回起動時に「自宅周辺（共有時に隠す範囲）」を設定する。既定は半径1km。スキップ可能だが、スキップした場合も**走行の始点・終点から200mは常に隠す**（`maskLine` の `trimEndsM`）。

**受け入れ条件**
- [ ] 隠す範囲を設定しないと、共有系の機能（招待状の作成）を使う前に設定を促される
- [ ] 隠す範囲の中心・半径は、他のユーザーのどの画面・どのAPI応答にも含まれない

## 1. 白地図（マイ地図）

走った道だけが線として残る地図。普通のナビ地図に切り替えられる。

### 表示
- **マイ地図（白地図）**：背景は海岸線・湖・県境程度の最小限。走った区間を太い緑線で描く。未走行の道はごく薄く点線で描く（どこに道があるか分かる程度）。
- **ナビ地図**：一般的な地図タイル。走った区間を細い緑線で重ねる。
- **写真ピン**：立ち寄りスポットに写真の丸いピンを立てる。同じ場所に複数ある場合は最新を表示し、件数バッジを付ける。
- **行きたい道**：招待状などで保存した区間をオレンジの点線で描く。
- **統計**：走った距離（区間の合計）、開拓率（`coverage`）、記録した日数。

### 地図が育つ様子の再生
- 白紙の状態から、走行を古い順に線が伸びるアニメーションで描く（`growthTimeline`）。各走行の日付を表示する。

### 開拓率の定義
- 分母：読み込んでいる地域の道路区間の総延長。生活道路（`residential`）は分母から除く想定（多すぎて率が上がらないため。`coverage` の `filter` で調整）。
- 分子：そのうち走った区間の長さ。

**受け入れ条件**
- [ ] 走行を保存すると、走った区間がすぐマイ地図に緑線で描かれる
- [ ] マイ地図とナビ地図の切り替えで、表示位置・ズームが保たれる
- [ ] 記録が0件のとき、白紙の地図と「最初の道を走りましょう」の案内が出る
- [ ] 再生は記録の古い順に進み、最後に通常表示に戻る
- [ ] 1,000回分の走行があっても地図の表示が2秒以内（区間単位で描くため、走行回数に比例して重くならない）

## 2. 走行記録と写真

### 記録の流れ
1. **停車中に**「記録を開始」を押す
2. 走行中は画面操作なしで GPS を記録（画面を消しても記録が続くのが理想。技術選定で差が出る点。`docs/05`）
3. 停車して「走行を終える」を押す
4. 保存画面で、走行日・愛車・タイトル・メモを確認し、立ち寄り候補に写真を付けて保存

### 記録データの処理（保存時）
| 処理 | 関数 | 内容 |
|---|---|---|
| ノイズ除去 | `cleanTrack` | 精度50m超の点、時速250km超の飛び、3m未満の微小移動を捨てる |
| 統計 | `rideStats` | 距離、走行時間（停車除く）、平均・最高速度 |
| 立ち寄り候補 | `detectStops` | 半径60m以内に5分以上とどまった場所を候補として提示 |
| 走った区間の判定 | `matchEdges` | 軌跡を道路区間に当てはめる（本番は専用APIへ置き換え推奨） |
| 初めての道 | `firstTimeEdges` | その走行より前に走っていない区間 |
| 保存用に間引き | `simplify` | 誤差10m程度で間引いて保存・描画用にする。生データは別保存 |

### 写真
- 保存画面またはアルバムから写真を追加できる。
- 写真の位置は「EXIFの位置 → 撮影時刻から補間 → 手動で配置」の順に決める（`placePhotos`）。補間で置いた写真には「位置を確認」を表示し、ドラッグで直せる。
- **アップロード前に写真のEXIF位置情報を削除する。** 位置はアプリのデータとして別に持つ。

### 誤操作への配慮
- 「走行を終える」を押し忘れた場合：30分以上ほぼ移動がなければ通知で確認し、最後に動いた時点で区切る。
- 記録を途中でやめる（保存しない）ことができる。やめる前に確認を挟む。

**受け入れ条件**
- [ ] 記録の開始・終了ボタンは、走行中（時速10km以上）は押せない、または確認が出る
- [ ] 2時間の走行を記録して保存でき、距離の誤差が実距離の±5%以内
- [ ] 5分以上の休憩が立ち寄り候補として出る
- [ ] 写真をアップロードしたファイルにEXIFの位置情報が残っていない
- [ ] 通信できない場所でも記録が続き、通信が戻ったら保存できる

## 3. 未走行ルート提案

### 入力
| 項目 | 選択肢 |
|---|---|
| 空き時間 | 1〜8時間（休憩込み） |
| 出発地 | 現在地／自宅／地図で指定 |
| 気分 | 海を見たい／峠を走りたい／湖でのんびり／カフェに寄りたい／おまかせ |
| 避けたい道 | 狭い山道／高速道路（複数選択可） |

### 提案の考え方（`suggestRoutes`）
- 出発地から出て出発地に戻る**周回ルート**を探す。同じ区間・同じ交差点は2回通らない。
- 空き時間の80%を走行に、20%を休憩に割り当てる（`restRatio`）。
- 点数 = 未走行の距離×2.5 ＋ 気分に合う距離×3 ＋ 行きたい道の距離×5 − 高速道路の距離×2 ＋（空き時間を55%以上使うなら加点）
- 似たルートばかりにならないよう、区間の55%以上が重なる候補は除いて上位3件を出す。
- **二輪通行止め・二輪規制のある区間は、条件に関係なく使わない**（`motorcycleBanned`）。

点数の重みは試作で決めた初期値です。テスト公開で「実際に走られたルート」を見て調整してください。

### 表示
- 各候補に、所要時間の目安（休憩込み）、未走行区間の距離、立ち寄り先、**提案の理由**を表示する。
- 理由の例：「いつもの『県道8号』の先に、まだ走っていない『茶屋峠道』が4.2kmあります。」（`formatReasonJa`）
- 地図では、走ったことのある区間を緑、未走行区間をオレンジで描く。
- 「このルートで走る」でナビアプリに渡す、またはアプリ内で点線ガイドとして表示する。

### 注意書き（常に表示）
「所要時間は目安です。通行規制・道路状況は出発前に確認してください。」

**受け入れ条件**
- [ ] 提案はすべて出発地で始まり出発地で終わる
- [ ] 提案の所要時間（休憩込み）が空き時間を超えない
- [ ] 「狭い山道を避ける」を選ぶと、狭い山道を含む提案が出ない
- [ ] 二輪規制のある区間を含む提案が出ない
- [ ] 条件に合うルートが無いとき、条件の変え方を案内する
- [ ] 半径50km程度の地域で、提案が3秒以内に出る

## 4. 道の招待状

### 送る
1. 走行記録を選ぶ（区間を絞ることもできる）
2. 写真とひとこと（140字まで）を付ける
3. 友達（アプリ内）に送る、またはリンクを共有する

**送る前に必ず自宅周辺を取り除く**（`buildInvite`）。取り除いた結果をプレビューで本人に見せる。

### 受け取る
- 招待状を開くと、写真・ひとこと・地図上の道・立ち寄り先・**自分にとっての未走行距離**が見える。
- 「マイ地図に保存」で、未走行の区間が「行きたい道」になる（`acceptInvite`）。ルート提案で優先される。

### 実走の通知
- 受け取った人が招待状の道をすべて走ると（`inviteProgress`）、「送り主に知らせますか？」と聞く。**知らせるかどうかは受け取った本人が選ぶ。** 知らせた場合、送り主に「招待した道を○○さんが走りました」と通知し、写真や感想を返せる。

### 招待状に含めないもの
生の軌跡、走行の日時（日付は任意で表示）、速度、隠す範囲の位置、隠す範囲内のスポット・写真。

**受け入れ条件**
- [ ] 招待状のデータに、隠す範囲の中の点が1つも含まれない
- [ ] 招待状のデータに、走行時刻・速度が含まれない
- [ ] 受け取った人だけが招待状を開ける（リンク共有の場合はリンクを知っている人）
- [ ] ブロックしている相手には送れない
- [ ] 実走の通知は、受け取った人が許可した場合だけ送られる

## 5. 履歴とアルバム（MVPでは簡易版）

- 走行の一覧（新しい順）。愛車で絞り込める。
- 1回の走行を開くと、統計（距離・初めての道・立ち寄り）と写真のタイムライン（`buildTimeline`）が見える。
- 「白地図でリプレイ」で、その走行の線を描くアニメーション。
- 走行の削除（確認あり）。削除すると白地図からも消える。
