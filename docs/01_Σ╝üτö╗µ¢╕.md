# 01 企画書

## ひとことで

**走った道で、自分だけの地図が育つ。** バイクの旅を白地図に残し、まだ走っていない道を次の冒険として提案するアプリ。

## 解決したいこと

バイク乗りの多くは、こんな状態にあります。

- **いつも同じ道を走ってしまう。** 新しい道を探すのは面倒で、結局おなじみのルートに戻る。
- **走った記録が残らない。** 写真はカメラロールに埋もれ、どこを走ったかは記憶頼み。
- **人気スポットの情報はあふれているが、「自分にとって新しい道」は教えてくれない。**
- **友達との「どこ行く？」が決まらない。** お互いがどこを走ったか分からない。

## コンセプト

| 柱 | 内容 | スライド |
|---|---|---|
| 自分だけの地図が育つ | 白紙の地図に、走った道だけが線として残っていく。写真もピンで残る | 1 |
| 次の冒険が見つかる | 履歴から「まだ走っていない道」を組み合わせて、空き時間に合うルートを提案 | 2 |
| 道の招待状を送る | 「いい道だった」を友達に送る。受け取った人は地図に保存して走りに行く | 3 |
| 友達と地図を重ねる | お互いの地図を重ねて、二人とも未開拓の場所を探す | 4 |
| 現地メモを次の人へ | 駐輪場所・路面・入口の坂など、行く前に知りたい情報を写真付きで残す | 5 |
| 冒険アルバムができる | 1日の走行と写真が自動でアルバムになり、短い動画でも共有できる | 6 |
| 仲間とつながる | QR/IDでアカウント交換、DMで次の旅を相談 | 7 |

スライドの画像は `docs/slides/` にあります。

## ターゲット

**主なターゲット：週末にソロツーリングをする中型〜大型バイクのライダー**

- 月に1〜4回、半日〜1日のツーリングに出る
- 行き先は「なんとなく」決めることが多い
- SNSに写真は上げるが、走行ログまでは管理していない

**次のターゲット：少人数でツーリングする仲間（2〜4人）**

- 行き先決めをLINEなどでしている
- 誰かが「いい道あった」と言っても、その場で終わってしまう

## 提供する価値

1. **走るたびに地図が埋まる達成感。** 「開拓率」「初めての道○本」が次に走る理由になる。
2. **「今の自分に合う新しい道」が見つかる。** 人気順ではなく、自分の履歴と空き時間から提案する。
3. **思い出が勝手に整理される。** 走行と写真が日付・愛車ごとにまとまる。
4. **友達の「いい道」が、実際の冒険につながる。** いいねで終わらず、走った感想が返ってくる。

## 既存サービスとの違い

| 種類 | 得意なこと | ミチノートの違い |
|---|---|---|
| ナビアプリ | 目的地までの最短・最適な道案内 | 目的地ではなく「まだ走っていない道」を軸にする。ナビ地図との切り替えは用意する |
| ツーリング記録・ログアプリ | 走行ログの記録、距離や速度の集計 | 記録を「白地図を埋める体験」にし、次のルート提案に使う |
| スポット情報サイト・SNS | 人気の場所や絶景の情報 | 人気ではなく自分の未開拓が基準。投稿にはライダー目線の実用情報（駐輪・路面）を添える |

※ 具体的な競合アプリの機能は変わりやすいので、着手前に最新の状況を調べ直してください（`docs/08` の未決事項に記載）。

## 最初に作るもの（MVP）

スライド7の「最初の開発」に合わせて、次の4つに絞ります。

1. **白地図（マイ地図）**：走った道が残る地図と、ナビ地図の切り替え
2. **写真記録**：走行の記録・保存、立ち寄りスポットと写真
3. **未走行ルート提案**：空き時間と気分から周回ルートを提案
4. **道の招待状**：走った道を友達に送る・受け取って地図に保存する

交流機能（地図を重ねる、DM、現地メモ、アルバム動画）は段階的に追加します（`docs/06`）。

## 収益化の案（未決）

まだ決めていません。考えられる案を挙げておきます。

- **無料＋有料プラン**：無料は記録と白地図、有料で提案の回数・条件、アルバム動画、地図の重ね合わせなど
- **地域パック**：遠方ツーリング向けに地域ごとの道路データ・おすすめを提供
- **広告は慎重に**：位置情報を扱うアプリなので、行動データを使った広告は信頼を損ないやすい

## 成功の目安（仮）

| 指標 | 目安 | 意味 |
|---|---|---|
| 初回記録の保存率 | インストールした人の50%以上 | 最初の体験が成立しているか |
| 2回目の記録までの日数 | 中央値14日以内 | 次も走りたくなっているか |
| 提案ルートを実際に走った割合 | 提案を開いた人の20%以上 | 提案が役に立っているか |
| 招待状の保存率 | 受け取った人の40%以上 | 招待状が冒険につながっているか |

数字は仮置きです。テスト公開で実測して見直してください。

## リスクと対策

| リスク | 対策 |
|---|---|
| 位置情報（特に自宅）が漏れる | 自宅周辺を自動で隠す処理をサーバーと端末の両方で行う。初期は「自分だけ」が既定（`docs/07`） |
| 走行中のスマホ操作を誘発する | 記録の開始・終了は停車中に行う設計。走行中は操作不要にする |
| 提案した道が通れない・危険 | 二輪規制のある道は提案しない。所要時間は「目安」と明記し、道路状況の確認を促す |
| 道路データの整備コスト | まずは1〜2地域に絞ってテスト公開する |
| 投稿情報の古さ・誤り | 訪問日を必須にし、古い情報を区別して表示する（スライド5） |
